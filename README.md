# drewneilson.com — fictional demonstration

The active site contains made-up Jobs, Projects, and Ideas for testing the content model. It does not present these as Drew's work. Every page carries a demonstration notice. Nothing is deployed.

## Open locally

In Terminal in this folder, run `npm run dev`, then open the local address Astro prints. Control-C stops the preview. On a fresh machine, run `npm ci` first.

## One piece, one file

Copy a file from `templates/` into `src/content/pieces/`. Name it descriptively, such as `new-project.md`. The filename is its ID and URL (`/pieces/new-project/`). Edit its short information block and write freely underneath. Set `draft: false` to show it locally. Missing `draft` defaults to true.

Required fields: `title`, `kind` (`job`, `project`, `idea`), and `summary`. Optional fields: `label` (short map name), `role` (for jobs), `status` (development stage), `attribution`, `connections`, `draft`. None of these requires a story to be its own node. A node's body can contain any appropriate narrative, headings, or anecdotes.

The site automatically supplies its page, card or job listing, incoming relationships, and map placement. No coordinates, layout values, order numbers, or separate relationship file are needed. Within each type, pieces are sorted by title.

## Connections stay with the piece

For example, in `wayfinding.md`:

```yaml
connections:
  - to: harbor-studio
    relation: part-of
  - to: clarity
    relation: led-to
    note: "What this project helped reveal."
```

`to` is another file's ID, without `.md`. The current file is the source. `note` is optional. Record a relationship once; the other page automatically shows its reverse wording.

| relation | Source page | Target page | Direction |
|---|---|---|---|
| part-of | Part of | Includes | Directed |
| led-to | Led to | Emerged from | Directed |
| informed | Informed | Informed by | Directed |
| related | Related to | Related to | Symmetric |

A connection can be followed from either page without reversing its meaning. Distinct relationship types and opposite directed relationships may coexist between the same subjects. Duplicate symmetric links (even entered in reverse), duplicate identical directed links, self-links, and unknown targets produce explanatory build errors. Drafts and all relationships involving them are omitted from the visible site.

## Where things appear

- Jobs: work-context section, own pages, and map/list.
- Projects: project section, own pages, and map/list, regardless of completion or employment context.
- Ideas: idea section, own pages, and map/list.
- Stories: prose inside any of those pages, not a fourth type.

`src/data/site.ts` selects the featured and secondary projects. Other projects appear automatically in the regular cards. This is a presentation choice, not a requirement when adding a piece. Node positions are generated by type and title; they are not saved in the content. The map remains a stable layout with selection, side profiles, zoom, pan, keyboard selection, and a phone-friendly List view. Directed relationships show arrowheads on selection; related links do not. The page and side panel always explain the relation in words.

## Demo tour

1. Wayfinding pilot → Clarity can be subtraction → Field Guide: a Project leads to an Idea that informs another Project at another Job.
2. Harbor Studio: one Job with multiple Projects.
3. Listening Bench: an unfinished personal Project without a Job.
4. Pocket Weather: a short, isolated Project with no connections.
5. Small choices: receives several connections with different meanings.
6. Hidden draft: an intentionally invisible fixture.
7. Wayfinding: long-form page with headings and a quotation; other nodes are deliberately short.

These examples are a starting test collection, not an exhaustive taxonomy or a template for Drew's career.

## Preserved personal content

`reference/personal-content/pieces/` holds all 16 previous personal content files unchanged. Their original connections are in `reference/personal-content/relationships.json`. The untouched V3 HTML and earlier editorial references also remain under `reference/`. These archived files are not loaded by Astro. Their old classifications have not been decided or silently converted to the new model. Reintroducing them will be a deliberate migration; do not copy old frontmatter unchanged into the new collection.

## Verify

Run `npm run check` and `npm run build`. `dist/` is generated output. The private GitHub repository and Cloudflare configuration are unchanged by this local demonstration. Publication remains a separate decision.
